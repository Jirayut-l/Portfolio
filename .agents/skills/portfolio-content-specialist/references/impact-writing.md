# Backend Impact Writing Guide

Backend developers often struggle to "show" their work visually. This guide helps frame technical backend achievements as high-impact portfolio content.

## Impact Formula
**[Action Verb] + [Specific System/Feature] + [Technique/Tool] + [Quantifiable Result]**

### Examples:
- *Weak:* "Managed microservices for FWD insurance."
- *Strong:* "Orchestrated 3 high-availability microservices for complex business logic, ensuring 99.9% uptime for core insurance processing."
- *Weak:* "Developed web APIs using C#."
- *Strong:* "Refactored legacy stored procedures into C# .NET APIs, reducing database load by 35% and improving maintainability."

## Backend Impact Verbs
- **Performance:** Optimized, Accelerated, Scaled, Throttled, Cached, Compressed.
- **Reliability:** Hardened, Safeguarded, Orchestrated, Decoupled, Synchronized.
- **Efficiency:** Streamlined, Refactored, Consolidated, Automated.

## Common Metrics for Backend Portfolios
- **Latency:** ms reduction, % faster response times.
- **Throughput:** Requests Per Minute (RPM), Events Per Second.
- **Reliability:** Uptime %, Error rate reduction.
- **Efficiency:** CPU/Memory usage reduction, Database query optimization %.
- **Productivity:** Deployment time reduction, Code coverage %.

## Visualizing "Invisible" Work
When a project is purely backend:
1. **Focus on the "Key Impact" stat**: This is the most visible part of the card.
2. **Use Architectural Icons**: Use `IconDatabase`, `IconServer`, `IconCloud`, or `IconCode` to categorize the work.
3. **Mention the Consumer**: "Built a gRPC API *used by 3 mobile apps and a web dashboard*." (Adds scale and context).
